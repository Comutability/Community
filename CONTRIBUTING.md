# Contributing to Comutability

**Status: Proposed guidance, subject to community adoption.**

You can contribute without writing code. We welcome bug reports, usability testing, documentation, accessibility ideas, translations, designs, research and code.

## Getting started

1. Look for an existing issue or discussion before creating a duplicate.
2. Explain the real problem and whom it affects.
3. Prefer small, focused changes and link them to a relevant issue when possible.
4. For code, include test steps and describe significant dependencies or risks.
5. Be open about substantial AI assistance so reviewers know what requires verification.
6. Do not include passwords, API keys, personal information or copyrighted material you do not have permission to contribute.

Repository-specific contributor instructions and licences take precedence over general guidance.

## Review

A contribution is a proposal, not an automatic commitment to include or maintain it. Human maintainers assess impact, safety, usability, accessibility and long-term maintenance.

## Contributions and rights

Before accepting external code, each software repository must publish a clear open-source licence and contribution policy. This draft does not establish a copyright assignment or require a contributor licence agreement.
