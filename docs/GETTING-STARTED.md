# Start Here: Users, New Contributors and Invited Developers
**Status: proposed onboarding handbook.**

## I want to use Comutability software

1. Open the [organisation](https://github.com/Comutability) and pick a project with an actual **release**.
2. Read its README, supported platforms, licence and known limitations.
3. Use release downloads only from trusted project pages; verify checksums/signatures when provided.
4. Follow the project's installation and privacy documentation. An idea, prototype or Base44 concept website is **not** automatically downloadable or independently validated.
5. Report issues without passwords, personal files or confidential data.

## I have an idea

Search [Community issues](https://github.com/Comutability/Community/issues), describe the specific problem, current alternatives, people helped and expected outcome, then invite feedback. A proposed tool isn't scheduled just because it has an issue.

## I want to contribute without coding

Welcome! Useful contributions include documenting a confusing step, writing examples, translating user journeys, testing with synthetic files, reviewing accessibility, explaining competing tools and verifying bugs.

## I want to code or use Claude

1. Choose a public, accepted issue and check whether a maintainer is available.
2. Read the repo's licence, `README.md`, `AGENTS.md`, `CLAUDE.md` and test commands.
3. Fork the project or work on an approved feature branch, never commit secrets.
4. Ask Claude to implement only the approved issue, with tests and docs; review its output yourself.
5. Open a PR, disclose substantive AI assistance, state **tests actually run** and any risks. Respond to review.
6. Human maintainers decide whether and when changes merge/release.

## I want to join the GitHub organisation

A public contributor does not need organisation membership. Named team access is offered **selectively** as trust and project needs develop. Contributions and maintainership are different things. Membership is not guaranteed, and temporary or project-specific access is preferred.

## I use Base44 on an included project

Coordinate with the project's named maintainer, who should decide which editor is source-of-truth for a change. Do not simultaneously edit GitHub and Base44 unsynchronised. Back up and test integration changes; use dedicated vendor credentials.
